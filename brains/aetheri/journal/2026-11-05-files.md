# Files navigation and selected-document editing

5 November 2026. The first Files view now browses a held directory tree and opens
a selected text file in a separately owned Terminal/editor. This advances an
ordinary app workflow; it does not complete the OS, install an app authority or
replace the planned document broker. Contract and CLI: [Files](../../../spec/files.md).

## Implementation

The original C17 model separates complete directory snapshots, raw names,
display labels, filtering, selection and held parent navigation from SDL. Limits
are 4,096 entries, 64 child levels and 255-byte names/queries. Links and special
entries are displayed but not opened. Failed scans/enter operations keep the
previous view. The SDL view has keyboard/pointer navigation, hidden filtering,
DE/EN, contrast, text scaling and native move/resize. Long labels are bounded
before rasterization; rejected queries cannot activate a retained matching prefix.
Very small 200-percent viewports explicitly require enlargement before activation.

Files uses `posix_spawn` with literal argv and a selected parent/file witness on
3/4. Terminal executes the original editor directly in a fresh PTY. The editor
compares the named inode with the held witness before reading and retains its
existing load/save/conflict/uncertainty rules. UI close preserves dirty-content
choices; Files waits for its original direct Terminal child and refreshes after
its end. Neither process creation nor EOF is readiness/end proof. Unknown child
observation does not permit a replacement start.

The direct-editor profile refuses cooperative Ctrl+Z/SIGTSTP suspension because
it has no shell to resume the job. Actual Ctrl+Z, continued editing and save are
tested; ordinary foreground-shell editor suspend/`fg` remains unchanged. Terminal
status/hints distinguish the direct editor from its shell mode.

## Executed checks

Final Release and ASan+UBSan builds both pass all **42 affected groups**, taking
104.06 and 167.95 seconds respectively. These cover the three new Files groups,
existing text/editor/PTY/shell/Terminal/Settings, Compose, desktop and compositor
input/clipboard behavior. The build command inventory confirms instrumentation
on Files model/launcher/view, editor file I/O, PTY and the new C tests. No test
policy was weakened for these ordinary-user runs.

`files.launch` starts a real separate process and checks literal argv, 3/4 handoff,
closed extra descriptors, removed `WAYLAND_SOCKET`, signal mask, process group and
original direct-child ownership. `files.native` exercises actual Wayland input and
three-output pixels, long names, filter overflow, hidden state, visible selection,
resize/200-percent refusal, idle, selected-file save, dirty-close cancel, hostile
literal filenames and waiting for the original document pair.

A copied-source negative control retains the unchanged model test: the positive
passes, while removing the selected witness's inode comparison fails. This proves
that the replacement case detects the omitted comparison; it is not general
authorization or volume-identity evidence.

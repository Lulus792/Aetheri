# Private password dialog

The managed cover can admit a dedicated SDL3 password dialog on an
inherited Wayland stream. The compositor checks the stream against the
original managed lock parent and admits one surface. All three displays
present the cover before it draws the dialog on the first display. The
dialog receives focus only after the first composed frame has presented
and physical input is neutral. The regular desktop keeps its processes
and windows behind the cover.

The first native layout uses a fixed 436 by 356 pixel opaque panel with
local time, account and a password field, in English or German. The
password buffer is cleared on submit, Escape and focus loss. A bounded
mask is the only draft data sent to the renderer. The separate
credential channel forwards each attempt to the original controller.
See the [session contract](../../../spec/session.md#private-password-dialog).

## Native checks

The final Release run `e5f134d571c2` passes all 11 selected tests, with
the known nested baseline failure outside the set. The new compositor
test observes black frames before the third display is acknowledged,
then the visible English focus and mask on the first display. Escape
clears the mask. Key and pointer events stay away from the ordinary
client while locked. Two idle samples report 26 commits each.
Closing the credential peer ends the dialog cleanly and leaves the
covered scene black. In the Debug build, AddressSanitizer and
UndefinedBehaviorSanitizer cover the dialog, compositor and both
unlock tests. All three selected tests pass, with 29 commits in
both idle samples.

Private carrier case `d0e16659dc55` uses synthetic credentials with
the actual PAM modules. The controller pins the original graphical
sender, receives the password only over its credential channel and
checks each attempt with a separate worker. A wrong password gives the
visible German refusal. The correct password produces an accepted
result. Holding Enter after submitting delays ordinary focus and
release. Once Enter is up, every pixel matches the original output
frames at 1920×1080, 2560×1440 and 3840×2160. The same application
process receives a fresh key. A stale release during the next lock is
rejected, and killing the original view leaves all three outputs black
and closes the managed channel.

## Earlier observations

The first graphical cases passed PAM and restored the exact desktop.
Their dialog capture could accept a client buffer as an output frame.
The first dedicated test exposed the 436 by 356 scanout buffer after
capturing the initial black cover. An explicit black scene rectangle
still produced that result. The pinned wlroots render-list path omits a
redundant opaque black rectangle at integer scale. The compositor now
holds rendering on the primary output during the private view, so the
positive presentation covers the composed frame. Both regression and
PAM fixtures require the original output dimensions.

The original release callback could also schedule a fresh redraw from
each surface-buffer release. The current event loop dispatches release
as a wake-up and only repaints for pending changes.

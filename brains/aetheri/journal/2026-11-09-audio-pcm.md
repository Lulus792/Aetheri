PCM FD to a finite confined UID 1000 user service and an independent host capture.
The final diagnostic preserves the complete reference tone. It does not install
normal device services or establish physical audio support.

## Implementation and scope

The [diagnostic contract](../../../spec/audio-pcm-device.md) describes the native
C17 probe, root-only baseline, temporary device type, original user-service
observer and retirement rules. No dependency version changes. Only the selected
virtual playback node is relabeled; its root:audio ownership, mode 0660 and ACL
are not broadened. Ordinary direct opens fail before and after. Their EACCES is
not claimed as independent proof of a MAC denial.

The initial code review corrects a context-method/attribute collision and keeps
before/after denial logs distinct. The diagnostic gets its own
`test_audio_pcm_device.py` filename: the existing seven-case synthetic PCM
verifier is restored unchanged and rerun. This avoids replacing an existing
CTest entry with a root-only administrative fixture.

`boot-hda` now starts paused with virtual output and a `none` backend. The
controller retains a second protected AF_UNIX QMP endpoint for capture, leaving
the original endpoint available for ordinary status/SSH/poweroff. Explicit
capture stop follows actual guest shutdown and precedes original QEMU exit.
Pinned-tool deprecation diagnostics are retained. Unknown commands never replay.
Plain boot/install, the original carrier and physical media are not changed.

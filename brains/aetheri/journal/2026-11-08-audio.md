# Private audio transport foundation

## Result and boundary

An original finite C17 playback diagnostic now sends stereo PCM through a real
PipeWire 1.6.11 graph in the enforcing carrier. Independent captured bytes match
440/880Hz channels for 48000, 96000 and 257 frames, with zero padding outside the
signal. Release and ASan/UBSan pass four CTest groups each: profile/parser,
PCM-verifier sensitivity,15 invalid CLI requests and seven real private graphs.
The latter also prove silence, server-loss/interrupt failure and a 15 second
unstarted deadline. Failure never reports drained success. Maximum observed
sample error is 3.701e-9 in both builds; paired captures have identical hashes.

This is not audio on the HP/USB image or an installed service/API. No ALSA,
WirePlumber, Bluetooth, device/profile switching, recording permission or Settings
control is implemented here. The next integration is an actual virtual sound
card and independently captured output, then per-user service/device policy and
physical headphone acceptance. Full everyday-OS scope remains active.

## Corrections discovered by real execution

The first extraction rejects the signed archive's unselected sr@latin locale
name. Admit the literal @ character in otherwise bounded canonical paths and add
a regression; never relax traversal/duplicate/type/content checks. The corrected
prefix passes strict C17 link/version checks and actual ELF inspection.

The first graph detects 1024 missing initial RIGHT-channel frames while LEFT is
fully correct. Sequential linking had already activated the producer after the
first link. Keep it inactive, bind both actual original stereo ports, then signal
the retained process to start once. This fixes the actual captured signal; the
verifier is not loosened. Its independent counterexamples reject missing early
right-channel samples, channel swaps, dropped frames, nonfinite/truncated data
and silence falsely treated as a tone.

The diagnostic bounds turns, checks format/data/chunk/alignment and guards failed
properties allocation so explicit routing never becomes default routing. Those
allocation guards are source-reviewed, not fault-injected acceptance. CONNECTED
is graph export and DRAINED is local stream completion, never physical audibility,
normal app readiness or authority lease settlement.

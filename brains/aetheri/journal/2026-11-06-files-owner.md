# NexaUI Files in the development desktop

6 November 2026. A new explicit `--files-ui nexaui-owned` start profile selects
our own Files view through the existing fixed desktop owner. Settings selection
is independent: Files works alongside SDL Settings or our own NexaUI Settings.
The default remains SDL. No SDK version, normal service, production policy or
public lifecycle capability changes. See the [guide](../../../spec/development-session.md)
and [Files contract](../../../spec/files.md#opt-in-nexaui-view).

## Selection and lifetime

The separate `aetheri-files-v1` profile binds the executable, nineteen compiled
model/controller/dependency inputs, five presentation/build/notice inputs, raw
CMake cache and reviewed SDK metadata/library. The source sets and field shape
are frozen for that kind. Files does not depend on an unused SDL Files executable
or the upstream Settings example. The SDK remains 0.1.18/e71ee30.

The root controller computes the canonical binding before seat/history/start
effects. Its original unprivileged supervisor repeats it before child creation,
then checks the original selection before each fresh Files spawn. Changed inputs
return the existing F launch-error reply without fallback or a process. A retained
live child is reused before rehashing; it is not silently replaced after an edit.
Files and Settings have separate recorded selections and share one SDK library
entry in the eight-image runtime inventory.

Old records without Files fields retain SDL meaning. Stop retries use historical
recorded values without selecting current sources or a newer SDK. Shared bounded
SDK/cache readers preserve the existing Settings profile shapes and canonical
binding algorithm. The normal app command channel and original child/pipe
retirement remain unchanged. These mutable same-account checks are developer
consistency, not sealed packages, publisher trust or atomic execution admission.
